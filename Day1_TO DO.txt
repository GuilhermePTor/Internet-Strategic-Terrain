PROJECT SETUP WITH UV + GIT + GITHUB (WINDOWS)
Project: internet-as-strategic-terrain
GitHub repo: Internet-Strategic-Terrain
URL: https://github.com/GuilhermePTor/Internet-Strategic-Terrain
Built and tested on Python 3.12.5

=====================================================
STEP 1: INSTALL UV
=====================================================
winget install --id astral-sh.uv -e

Open a NEW terminal afterwards, then check it:
uv --version

Why: uv is one tool that manages Python versions, packages and
the virtual environment.

=====================================================
STEP 2: CHECK PYTHON VERSIONS
=====================================================
python --version
uv python list

Why: see what you already have before choosing a version to pin.

=====================================================
STEP 3: CREATE THE PROJECT
=====================================================
Go to your project folder, then run:
uv init

Creates pyproject.toml, .python-version, .gitignore, a src folder
and a README.

Why: from day one the project records what it needs, so it can
be rebuilt on any machine.

=====================================================
STEP 4: RECORD (PIN) THE PYTHON VERSION
=====================================================
uv python pin 3.12.5

Check it:
type .python-version
uv run python --version

Also make sure pyproject.toml contains:
requires-python = ">=3.12"

Why: everyone who runs the project uses the same Python.

=====================================================
STEP 5: FIX THE CERTIFICATE ERROR (WORK/SCHOOL NETWORKS)
=====================================================
If uv add fails with "invalid peer certificate: UnknownIssuer",
add --system-certs to the command (used in the steps below).

To make it permanent (then close and reopen the terminal):
setx UV_SYSTEM_CERTS true

Why: the network inspects HTTPS traffic with its own certificate.
This tells uv to trust the Windows certificate store.

=====================================================
STEP 6: ADD DEPENDENCIES (CREATES THE LOCKFILE)
=====================================================
uv add requests --system-certs
uv add --dev pytest --system-certs

Each command updates pyproject.toml and uv.lock.
(--dev means a development-only tool, not needed to run the project.)

Why: uv.lock pins the exact version of every package, including
sub-dependencies, so installs are identical every time.

=====================================================
STEP 7: VERIFY EVERYTHING IS PINNED
=====================================================
uv lock --check
uv tree

uv lock --check: confirms uv.lock matches pyproject.toml.
uv tree: lists all packages and their sub-dependencies.

=====================================================
STEP 8: WRITE AND RUN A TEST
=====================================================
Create a folder called tests, and inside it a file
tests\test_main.py with this content:

def test_addition():
    assert 1 + 1 == 2

Run it:
uv run pytest

Expected result: 1 passed

Why: a working test setup from the start catches breakage when
you change code or upgrade packages.

=====================================================
STEP 9: CHECK .gitignore
=====================================================
type .gitignore

It must contain the line:
.venv

Do NOT commit the .venv folder.

=====================================================
STEP 10: INITIALIZE GIT AND COMMIT
=====================================================
Check if this folder is already a git repo:
git status

If it says "not a git repository", run:
git init

Set your identity once (skip if already configured):
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Optional, removes the LF/CRLF warnings on Windows:
git config --global core.autocrlf true

Stage and commit:
git add .gitignore .python-version pyproject.toml uv.lock README.md src tests
git status
git commit -m "Pin Python version and dependencies"

Notes:
- The LF/CRLF warnings are harmless.
- Optional notes file (quotes needed because of the space):
  git add "Day1_TO DO.txt"
  or add it to .gitignore to keep git status clean.

Why: the commit saves the pinned Python version, the lockfile
and the tests, so the project can be rebuilt anywhere.

=====================================================
STEP 11 (MANDATORY): CONNECT TO GITHUB AND PUSH
=====================================================
Repo name: Internet-Strategic-Terrain
URL: https://github.com/GuilhermePTor/Internet-Strategic-Terrain

11a. Check whether the repo exists:
Open the URL above in a browser.

11b. IF THE REPO DOES NOT EXIST, create it:
- Go to https://github.com/new
- Repository name: Internet-Strategic-Terrain
- Leave it EMPTY: do not add a README, .gitignore or license
- Click "Create repository"

11c. Link the local project to GitHub:
git remote add origin https://github.com/GuilhermePTor/Internet-Strategic-Terrain.git

If it says "remote origin already exists", run this instead:
git remote set-url origin https://github.com/GuilhermePTor/Internet-Strategic-Terrain.git

Check the link:
git remote -v

11d. Rename the branch to main and push:
git branch -M main
git push -u origin main

A browser window may open to sign in to GitHub. Complete it.

11e. Confirm:
Refresh the repo page in the browser. The files should be there,
including .python-version, uv.lock and pyproject.toml.

If push fails with a certificate error (work/school network):
git config --global http.sslBackend schannel
Then run git push -u origin main again.

If push is rejected because the GitHub repo already has files:
git pull origin main --allow-unrelated-histories
(resolve any conflict, commit) then git push -u origin main

Why: GitHub is the backup and the shared copy of the project.

=====================================================
STEP 12: REBUILD THE ENVIRONMENT ANYWHERE
=====================================================
git clone https://github.com/GuilhermePTor/Internet-Strategic-Terrain.git
cd Internet-Strategic-Terrain
uv sync --locked --system-certs
uv run pytest

Installs exactly what uv.lock says. Fails if the lockfile is
out of date.

=====================================================
DAILY WORKFLOW
=====================================================
1. Write a small piece of code in src\internet_as_strategic_terrain\
2. Write a test for it in tests\
3. uv run pytest
4. git add .
5. git commit -m "Describe what you changed"
6. git push

Add a new package (updates uv.lock, then commit and push):
uv add PACKAGE-NAME

=====================================================
UPGRADING LATER (ON PURPOSE)
=====================================================
uv lock --upgrade
uv sync
uv run pytest
git add uv.lock pyproject.toml
git commit -m "Upgrade dependencies"
git push

=====================================================
FILES THAT MATTER
=====================================================
.python-version  -> the pinned Python version
pyproject.toml   -> what the project needs
uv.lock          -> exact versions of every package
tests\           -> the tests
.gitignore       -> keeps .venv out of git
